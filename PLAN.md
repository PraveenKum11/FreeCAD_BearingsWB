# Bearings Workbench for FreeCAD: Plan

The source of truth for scope, decisions and roadmap. Update it whenever a decision changes.

## 1. Vision and decisions

A FreeCAD workbench for inserting parametric rolling bearings, in the spirit of
[FreeCAD_FastenersWB](https://github.com/shaise/FreeCAD_FastenersWB). Pick a series and a
designation (or click a hole or shaft edge) and get a correctly sized bearing that stays
parametric.

Decided on 2026-10-09:

| Decision | Choice | Consequence |
|---|---|---|
| Audience | **Makers first** | Prioritize the sizes found in 3D printers, robots and RC: 608, 625, 688, MR/F miniature, flanged, LM8UU. Clearance and fit help matter more than ISO 281 life math. Printable bearings come early. |
| Codebase | **New repo**, not a fork of Fasteners | We copy ideas (CSV tables, command table, edge-snap, shape cache), not code. |
| License | **GPL-3.0-or-later** (decided 2026-10-14) | `LICENSE` holds the text; every source file has an SPDX header. The printable bearing came from the author's own MIT macro, so it can be relicensed. |
| Data | **Standard boundary dimensions plus computed internals** | CSVs hold only d, D, B, r (ISO 15 / maker-common), plus shielded width and flange dims for miniatures. Ball size, ball count, pitch diameter and raceways are computed (§4). No manufacturer catalog data is copied. |
| Target FreeCAD | **1.1.x** (tested with 1.1.3) | Avoid APIs that exist only in 26.x dev builds. |
| Versions | **First release is 1.0.0** (decided 2026-10-14) | The v0.1 … v0.5 headings in §8 are roadmap milestones, not package versions. `package.xml` says 1.0.0 until that release ships. |

## 2. What we borrow from Fasteners WB

| Fasteners WB | Bearings WB |
|---|---|
| `FsData/*.csv`: one table per standard | `BRData/iso15_<series>.csv`: one table per bearing series |
| `FsFunctions/FSmake*.py`: one generator per family | `BearingGeometry.py`: one profile builder per family (bearings are all bodies of revolution, so families share most of the code) |

| `AutoDiameter` + `MatchOuter` + `FSMoveToObject` | `MatchTo` = Shaft (bore) / Housing (OD), placed via the adjacent planar face normal |
| `CountersunkHoles` | **Seat cutter** (v0.3) |
| `FS3dpSettings` | **Printable bearing** (v0.2, the author's DeepGrooveBallBearing macro) |
| `FSSearchCmd` | **Find bearing**: by name, ID, OD or height (v0.2) |

Layering rule: `BearingGeometry` depends only on `Part` and `FreeCAD.Vector`. `BearingBase`
depends on Data and Geometry. Only `InitGui`, `BearingsCmd` and the `*Gui` modules touch `FreeCADGui`. So
everything except the commands can be tested headless.

## 4. Data and computed internals

### 4.1 CSV schema

```
Designation,d,D,B,r,B_shielded,D1,C1
608,8,22,7,0.3,,25,1.5
688,8,16,4,0.15,5,18,1.0
```

- `d`, `D`, `B`: bore, outside diameter and width in mm (ISO 15 boundary dimensions).
- `r`: minimum chamfer/corner radius `r_s min`.
- `B_shielded` (optional): width of shielded/sealed variants when it differs from the open
  width. This is common for 68x, 69x and MR miniatures (684 = 4×9×2.5, 684ZZ = 4×9×4).
- `D1`, `C1` (optional): flange outside diameter and flange width. If both are present, the
  row supports `Flanged` (F608, MF105, FR188, …). Inch FR rows use the shielded flange width.
- Inch R sizes (`inch_r.csv`) are the ABMA inch dimensions × 25.4. **Checked 2026-10-14**
  with `tools/dev/verify_skf.py`: R144, R166, R188, R3, R4, R4A and R12 match SKF exactly,
  and all closed widths match. Open widths differ for R6 (SKF 5.556 = exactly 7/32"; we
  have 5.558 from the rounded 0.2188", which SKF itself uses for R4A) and R8 / R10 (SKF
  lists open bearings 8.0 / 11.0 wide with the same d × D, apparently its own designs; the
  standard open widths are 1/4" / 9/32", kept). Nine small sizes (R2-5, R2-6, R2, R2A,
  R155, R156, R3A, R168, R1810) aren't sold by SKF; they and all FR flanges match a
  miniature vendor's chart.
- Linear bushings (`linear_lm.csv`) have their own columns: `d` (shaft), `D`, `L`, ring
  grooves `B` (between their outer faces), `W`, `Dg`, ball circuits `Rows`, and for the
  flanged variants `D1`, `H` (thickness), `PCD`, `K` (square side) and the counterbored
  hole `d1`, `d2`, `h`. The "Asian standard" LM dimensions are interchangeable between
  makers. **Checked 2026-10-14** against two makers' public tables: plain, long, LMF and
  LMK all agree, except LMK40LUU / LMK60LUU lengths (one table: 151 / 209, the other and
  the plain LM40LUU / LM60LUU: 154 / 211; we use 154 / 211).
- Lines starting with `#` are comments.
- Values were compiled from public ISO 15 boundary tables and common miniature listings.
  **Miniature shielded widths and flange dimensions are approximate.** Check them against a
  vendor sheet before relying on them for tight fits (tracked in §10).
- **Verified 2026-10-09 against SKF's public deep groove table** (git-ignored
  `tools/dev/verify_skf.py`, 4,192 SKF rows, matched by d × D, comparing open and closed
  widths):
  - Series 60, 62, 63, 68 and 69: every row SKF sells matches, including the wider
    shielded widths of 68x/69x miniatures (684ZZ = 4, 688ZZ = 5, 693ZZ = 4, …).
  - MR closed widths all match SKF's equivalent closed bearings. SKF sells most of these
    sizes only shielded, so open MR widths can't be checked against SKF.
  - Flagged MR62 (2×6×2.5) and MR115 (5×11×4). SKF's only 2×6 and 5×11 bearings are the ISO
    sizes 692 (2.3/3.0) and 685 (3/4), which our 69/68 tables already have. The MR rows
    follow the Minebea/NMB MR naming, so this is two size families sharing d × D, not a
    data error. Confirm against an NMB sheet.
  - Not in SKF's range (unverified): 636–639, 691, 6919, 6920, MR117, MR137.
  - The list table has no corner radius or flange data. See the per-bearing details
    check below for `r`. Flange data remain unverified.
- **Per-bearing details check, 2026-10-09** (SKF `details` endpoint: 146 records, one per
  matching size, fetched sequentially 3 s apart and cached outside the repo; SKF data is
  not committed):
  - Corner radius `r`: 136 of 146 matched. Adopted SKF's 7 standard ISO 582 values:
    688/689 0.15→0.2, 6804 0.3→0.6, MR52 0.05→0.08, MR62 0.1→0.15, MR106 0.1→0.15,
    MR126 0.15→0.2. **Kept** ISO values for 6816 (0.6), 6817 (1.0) and 6915 (1.0). SKF lists
    1.3 / 1.9 / 1.9 there, which are not ISO 582 radii, and SKF's own `ra` for 61816 (0.6) is
    below its stated `r`.
  - SKF data quirks to ignore: 61814 lists D1 = D, and 61808 lists d1 = D1.
  - The extracted data (27 columns) exists only locally, in the git-ignored
    `tools/dev/reference/skf_deep_groove_specs.csv`, made by `tools/dev/skf_scrape.py`
    (sequential, 3 s delay, cached in `tools/dev/.skf_cache/`, stops at the first non-200
    response). **Manufacturer catalogue data is never committed** (§1): this plan keeps
    only the conclusions drawn from it (adopted radii above, the error table in §4.2, the
    shoulder formulas in §8 v0.3).

### 4.2 Computed internals (deep-groove ball)

Given d, D, B (`wall = (D − d)/2`):

| Quantity | Formula | Sanity check |
|---|---|---|
| Pitch diameter `dm` | `(d + D)/2` | 6204: 33.5 |
| Ball diameter `Dw` | largest standard ball (ISO 3290 metric + inch fractions) ≤ `min(0.6·wall, 0.7·B)` | 6204 → 8.0 (real 7.938); 608 → 4.0 (real 3.969) |
| Linear bushing ball | largest standard ball ≤ `0.45·wall`; rows from the table, balls spaced 1.02·Dw between the seals | LM8UU → 1.5 mm, 4 × 13 |
| Ball count `Z` | `max(5, round(0.6·π·dm/Dw))`, capped so balls never touch | 6204 → 8 (real 8); 608 → 7 (real 7) |
| Inner raceway groove radius | `0.515·Dw` (ri/Dw = 0.515 is typical) | |
| Outer raceway groove radius | `0.525·Dw` | |
| Inner ring shoulder radius | `dm/2 − 0.3·Dw` | |
| Outer ring land radius | `dm/2 + 0.3·Dw` | |
| Shield thickness | `clamp(0.04·B, 0.1, 1.0)`; seal (RS) `clamp(0.1·B, 0.2, 2.0)` | |
| Shield recess in outer ring | `0.15·Dw` radial | |

**Validated against SKF details (143 bearings).** Errors are expressed as a fraction of the
section height D − d (positive = ours larger):

| Feature | SKF symbol | Our model | Mean error | SD |
|---|---|---|---|---|
| Inner ring shoulder Ø | d1 | dm − 0.6·Dw | +1.2 % | 4.6 % |
| Outer ring shoulder Ø | D1 | dm + 0.6·Dw | −2.0 % | 2.2 % |
| Shield recess Ø | D2 | dm + 0.9·Dw | −1.0 % | 3.3 % |

That's a fraction of a millimetre for maker sizes (608: ≈ 0.2 mm), so no retuning is
needed.

Raceway grooves are arcs in the 2D ring profile, so there is **no boolean for the rings**.
Only the cage needs a boolean.

## 5. The bearing object

`Part::FeaturePython` with proxy `BearingBase.BearingObject`.

| Property | Type | Notes |
|---|---|---|
| `Series` | Enumeration | 60, 62, 63, 68, 69, MR (v0.1) |
| `Designation` | Enumeration | `Auto` + rows of the series; the list refreshes when `Series` changes |
| `Closure` | Enumeration | Open, Z, ZZ, RS, 2RS. A single closure sits on the top face (z = 0) |
| `Flanged` | Bool | Ignored with a warning if the row has no flange data |
| `DetailLevel` | Enumeration | **Envelope** (1 solid, fast), **Standard** (rings + balls + shields), **Detailed** (adds a cage) |
| `MatchTo` | Enumeration | Shaft (match bore) / Housing (match OD); used when `Designation = Auto` |
| `BaseObject` | LinkSub | Circular edge to attach to (optional) |
| `Invert`, `Offset` | Bool, Distance | Flip direction / shift along the axis |
| read-only | | `FullDesignation`, `BoreDiameter`, `OuterDiameter`, `Width`, `PitchDiameter`, `BallDiameter`, `BallCount` |

Local frame: the axis is +Z, the bearing occupies **z ∈ [−B, 0]**, and the flange sits at
z ∈ [−C1, 0]. With an attachment, z = 0 lands on the clicked edge's face and the bearing
extends *into* the material. That means into the hole for Housing, and onto the shaft for a
shaft-end edge (whose face normal points away from the shaft). The direction comes from the
planar face adjacent to the edge (`ancestorsOfType`), with a fallback to the circle axis.

Designation strings, using maker conventions: `608`, `608Z`, `608ZZ`, `608-RS`, `608-2RS`,
`F608ZZ`, `MF105ZZ`.

Labels follow the designation (`608`, then `608-2RS` after a closure change) until the
user renames the object. Further bearings with the same designation get a counter:
`608_001`, `608_002`. Labels must be unique, and FreeCAD otherwise makes them so by
incrementing a trailing number: a second `608` became `609`, which reads as a different
bearing (fixed 2026-10-14).

Face colors (steel rings and balls, brass cage, grey shields, black seals) are computed in
`execute` and applied by the view provider (`DiffuseColor`).

## 6. GUI

- One toolbar "Bearings" with one insert command per series, each with its own SVG icon.
- If circular edges are selected, insert one bearing per edge with `Designation = Auto`.
  Edges come from the shaft (bore match) or the hole (OD match), depending on whether the
  radius matches a bore or an OD better. Otherwise, insert at the origin with a
  maker-friendly default (608, 625, 6300, 688, 695, MR105).
- Everything else is edited in the property editor, as in Fasteners.
- Toolbar "Bearing tools": **Find bearing** (search panel) and **3D-printable bearing**
  (task panel). Both are task panels, so the 3D view stays usable.
- Printable bearings are edited later on their `BearingParameters` datum. The
  `PrintableBearing` object next to the bodies shows the catalog match and any error.
- User-visible strings are plain English, not wrapped in `translate()`. Translations come
  with v0.5; wrap every string then, in one pass.

## 7. Testing

Headless tests use the standard library's `unittest` (no extra packages, so they run in
FreeCAD's own Python) and are run by FreeCAD's `freecadcmd`:

```sh
path/to/freecadcmd tests/run_tests.py                                  # everything, ~2 min
BEARINGS_TESTS=test_printable path/to/freecadcmd tests/run_tests.py    # one module
```

The runner exits with status 1 on any failure. One module per area (`test_data`,
`test_geometry`, `test_bearing_object`, `test_printable`); `DocumentTest` gives each test
a fresh document. Loops over many cases use `subTest`, so one failing case doesn't hide
the rest.

1. Every row (all series, LM and R included; LM in both flange shapes, without closures) ×
   {Open, Z, ZZ, 2RS} × {flanged if available} × {Envelope, Standard}, plus
   Detailed on 3 rows per series (smallest, middle, largest; the cage boolean is slow):
   `isValid()`, bounding box ≈ (D or D1, B_eff), bore clear, expected solid count.
2. Balls don't overlap rings (`common` volume ≈ 0) for representative sizes.
3. Internals sanity: 608 → Z = 7, Dw ≈ 4; 6204 → Z = 8, Dw ≈ 8.
4. FeaturePython: the Auto match picks 608 for a Ø22 hole (Housing) and for a Ø8 shaft (Shaft).
   Placement puts z = 0 on the face and the body inside the hole or on the shaft.
5. Save, reopen and recompute (proxy serialization).
6. Printable bearings: the preview (`preview_shapes`) matches a real build (volumes and
   bounding boxes of races, balls and cage), also after editing every parameter, which
   checks the sketch expressions against `groove_profile()` / `cage_profile()`.

GUI smoke test (`tests/gui/`): `FREECAD=path/to/FreeCAD tests/gui/run_gui.sh
tests/gui/gui_smoke.py <log>` drives the panels in the real FreeCAD GUI; the workbench
must be installed. Scripts end with `guikit.finish()`, which closes documents without
saving and exits the process, so the "save changes?" dialog can't block an unattended run.
The runner also kills that FreeCAD process if it outlives the script or a timeout.
`guikit` also closes any dialog that appears (message boxes, including macOS window-modal
sheets that `activeModalWidget()` doesn't report) and logs its text, so an unexpected
warning can't hang a run.

Don't name test scripts `inspect.py`. It shadows the stdlib module and freecadcmd silently
prints nothing.

Code style: `ruff format .` and `ruff check .` (settings in `pyproject.toml`; Ruff's
formatter is Black-compatible). Static type checking is not set up yet (§10).

### v0.2: Maker essentials (in progress)

- [x] **Printable bearing** (`PrintableBearing.py`, `PrintableBearingGui.py`,
  command `Bearings_PrintableBearing`):
  - Both macro modes: *Create races* (new App::Part "Bearing …") and *Groove selected body*
- [x] **Find bearing** (`BearingSearchGui.py`, command `Bearings_Search`; logic in
  `BearingData.search()` / `parse_designation()`): search by **name, ID, OD or height**,
  in any combination, with a ± tolerance.
- [x] **Linear bushings** (done 2026-10-14): series `LM`, family `linear`
  (`BRData/linear_lm.csv`, `BearingData.LinearRow`, `BearingGeometry.make_linear`):
  LM5UU–LM60UU and LM6LUU–LM60LUU, flanged LMF (round) and LMK (square, corners trimmed to
  the round flange diameter) via `Flanged` + `FlangeShape`. Envelope: the sleeve with its
  retaining ring grooves (plain) or flange with counterbored bolt holes. Standard: adds a
  seal at each end and the plastic ball retainer filling the space to the shaft, with a
  slot along each ball row (slightly wider than a ball). Detailed: adds one straight row of
  balls per circuit in the slots, running on the shaft. `Closure` is hidden for LM
  (always UU); `FlangeShape` is hidden for ball bearings. Not offered as printable bearings.
- [x] **Inch R-series** (done 2026-10-14): series `R` (`BRData/inch_r.csv`): R144, R155,
  R156, R166, R168, R188, R1810, R2-5, R2-6, R2, R2A, R3, R3A, R4, R4A, R6, R8, R10, R12,
  flanged FR variants where they exist. Ordinary deep groove rows, so detail levels,
  closures, edge snap, search and the printable catalog work unchanged.
- [x] **Flanged bearings in a hole** (fix, 2026-10-14): with `MatchTo = Housing` the flange
  rests on the face and only the body goes into the hole (it used to sit half inside).

## 9. Risks and notes

- **Accuracy of miniature data**: shielded widths and flange dims vary by vendor. Keep
  them in CSV so users can fix them easily, and flag them in the docs.
- **Performance**: Detailed mode on big assemblies. Keep the default at `Standard`, cache
  shapes by key, never fuse balls (compound only), and use one cage boolean.
- **Toponaming**: `BaseObject` references an edge by name (`Edge12`). It can break when
  the base changes, the same limitation as Fasteners. Revisit with FreeCAD 1.x's
  `App::PropertyLinkSub` + element maps later.

## 10. Open questions

- Static type checking (pyright or mypy). FreeCAD's modules are C++ extensions without
  type information, so a checker would mostly report unknowns. Options: the community
  `freecad-stubs` package, or checking only the modules that don't touch FreeCAD objects
  much (`BearingData`, the formulas in `BearingGeometry`). Decide before adding it; Ruff's
  pyflakes and bugbear rules already catch undefined names and common bugs.
- Repo name / Addon Manager display name ("Bearings").
- Verify flange dims (F/MF), corner radii, MR62/MR115 and the SKF-unlisted rows (§4.1)
  against an NMB/Minebea or other miniature-bearing vendor sheet.
- Candidates SKF lists that we don't have yet: series 160xx (16001–16020), 622xx/623xx
  wide-sealed, 617/x and 618/1.5–2.5 ultra-miniatures, inch R-series (already in v0.2).
