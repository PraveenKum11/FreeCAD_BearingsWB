# Bearings Workbench for FreeCAD: Plan

The source of truth for scope, decisions and roadmap. Update it whenever a decision changes.

## 1. Vision and decisions

A FreeCAD workbench for inserting parametric rolling bearings, in the spirit of
[FreeCAD_FastenersWB](https://github.com/shaise/FreeCAD_FastenersWB). Pick a series and a
designation (or click a hole or shaft edge) and get a correctly sized bearing that stays
parametric.

Decided on 2026-10-09:

| Decision | Choice | Consequence |
|---|---|---|
| Audience | **Makers first** | Prioritize the sizes found in 3D printers, robots and RC: 608, 625, 688, MR/F miniature, flanged, LM8UU. Clearance and fit help matter more than ISO 281 life math. Printable bearings come early. |
| Codebase | **New repo**, not a fork of Fasteners | We copy ideas (CSV tables, command table, edge-snap, shape cache), not code. We're free to pick the license (proposed **LGPL-2.1-or-later** to match FreeCAD; still open, see §10). |
| Data | **Standard boundary dimensions plus computed internals** | CSVs hold only d, D, B, r (ISO 15 / maker-common), plus shielded width and flange dims for miniatures. Ball size, ball count, pitch diameter and raceways are computed (§4). No manufacturer catalog data is copied. |
| Target FreeCAD | **1.1.x** (tested with `/Volumes/Silo/brew/FreeCAD.app` 1.1.3) | Avoid APIs that exist only in 26.x dev builds. |

## 2. What we borrow from Fasteners WB

| `FsFunctions/FSmake*.py`: one generator per family | `BearingGeometry.py`: one profile builder per family (bearings are all bodies of revolution, so families share most of the code) |

| `CountersunkHoles` | **Seat cutter** (v0.3) |
| `FS3dpSettings` | **Printable bearing** (v0.2, the author's DeepGrooveBallBearing macro) |
| `FSSearchCmd` | **Find bearing**: by name, ID, OD or height (v0.2) |

Layering rule: `BearingGeometry` depends only on `Part` and `FreeCAD.Vector`. `BearingBase`
depends on Data and Geometry. Only `BearingsCmd` and `InitGui` touch `FreeCADGui`. So
everything except the commands can be tested headless.

## 4. Data and computed internals

### 4.1 CSV schema

```
Designation,d,D,B,r,B_shielded,D1,C1
608,8,22,7,0.3,,25,1.5
688,8,16,4,0.15,5,18,1.0
```

- `d`, `D`, `B`: bore, outside diameter and width in mm (ISO 15 boundary dimensions).
- `r`: minimum chamfer/corner radius `r_s min`.
- `B_shielded` (optional): width of shielded/sealed variants when it differs from the open
  width. This is common for 68x, 69x and MR miniatures (684 = 4×9×2.5, 684ZZ = 4×9×4).
- `D1`, `C1` (optional): flange outside diameter and flange width. If both are present, the
  row supports `Flanged` (F608, MF105, …).
- Lines starting with `#` are comments.
- Values were compiled from public ISO 15 boundary tables and common miniature listings.
  **Miniature shielded widths and flange dimensions are approximate.** Check them against a
  vendor sheet before relying on them for tight fits (tracked in §10).
- **Verified 2026-10-09 against SKF's public deep groove table** (`tools/verify_skf.py`,
  4,192 SKF rows, matched by d × D, comparing open and closed widths):
  - Series 60, 62, 63, 68 and 69: every row SKF sells matches, including the wider
    shielded widths of 68x/69x miniatures (684ZZ = 4, 688ZZ = 5, 693ZZ = 4, …).
  - MR closed widths all match SKF's equivalent closed bearings. SKF sells most of these
    sizes only shielded, so open MR widths can't be checked against SKF.
  - Flagged MR62 (2×6×2.5) and MR115 (5×11×4). SKF's only 2×6 and 5×11 bearings are the ISO
    sizes 692 (2.3/3.0) and 685 (3/4), which our 69/68 tables already have. The MR rows
    follow the Minebea/NMB MR naming, so this is two size families sharing d × D, not a
    data error. Confirm against an NMB sheet.
  - Not in SKF's range (unverified): 636–639, 691, 6919, 6920, MR117, MR137.
  - The list table has no corner radius or flange data. See the per-bearing details
    check below for `r`. Flange data remain unverified.
- **Per-bearing details check, 2026-10-09** (SKF `details` endpoint: 146 records, one per
  matching size, fetched sequentially 3 s apart and cached outside the repo; SKF data is
  not committed):
  - Corner radius `r`: 136 of 146 matched. Adopted SKF's 7 standard ISO 582 values:
    688/689 0.15→0.2, 6804 0.3→0.6, MR52 0.05→0.08, MR62 0.1→0.15, MR106 0.1→0.15,
    MR126 0.15→0.2. **Kept** ISO values for 6816 (0.6), 6817 (1.0) and 6915 (1.0). SKF lists
    1.3 / 1.9 / 1.9 there, which are not ISO 582 radii, and SKF's own `ra` for 61816 (0.6) is
    below its stated `r`.
  - SKF data quirks to ignore: 61814 lists D1 = D, and 61808 lists d1 = D1.
  - The full extracted data is kept in `reference/skf_deep_groove_specs.csv` (27 columns).
    Regenerate it with `python3 tools/dev/skf_scrape.py`. The script is git-ignored, along
    with its cache in `tools/dev/.skf_cache/`. It is sequential with a 3 s delay, reuses the
    cache, and stops at the first non-200 response.

### 4.2 Computed internals (deep-groove ball)

Given d, D, B (`wall = (D − d)/2`):

| Quantity | Formula | Sanity check |
|---|---|---|
| Pitch diameter `dm` | `(d + D)/2` | 6204: 33.5 |
| Ball diameter `Dw` | largest standard ball (ISO 3290 metric + inch fractions) ≤ `min(0.6·wall, 0.7·B)` | 6204 → 8.0 (real 7.938); 608 → 4.0 (real 3.969) |
| Ball count `Z` | `max(5, round(0.6·π·dm/Dw))`, capped so balls never touch | 6204 → 8 (real 8); 608 → 7 (real 7) |
| Inner raceway groove radius | `0.515·Dw` (ri/Dw = 0.515 is typical) | |
| Outer raceway groove radius | `0.525·Dw` | |
| Inner ring shoulder radius | `dm/2 − 0.3·Dw` | |
| Outer ring land radius | `dm/2 + 0.3·Dw` | |
| Shield thickness | `clamp(0.04·B, 0.1, 1.0)`; seal (RS) `clamp(0.1·B, 0.2, 2.0)` | |
| Shield recess in outer ring | `0.15·Dw` radial | |

**Validated against SKF details (143 bearings).** Errors are expressed as a fraction of the
section height D − d (positive = ours larger):

| Feature | SKF symbol | Our model | Mean error | SD |
|---|---|---|---|---|
| Inner ring shoulder Ø | d1 | dm − 0.6·Dw | +1.2 % | 4.6 % |
| Outer ring shoulder Ø | D1 | dm + 0.6·Dw | −2.0 % | 2.2 % |
| Shield recess Ø | D2 | dm + 0.9·Dw | −1.0 % | 3.3 % |

That's a fraction of a millimetre for maker sizes (608: ≈ 0.2 mm), so no retuning is
needed.

Raceway grooves are arcs in the 2D ring profile, so there is **no boolean for the rings**.
Only the cage needs a boolean.

## 5. The bearing object

`Part::FeaturePython` with proxy `BearingBase.BearingObject`.

| Property | Type | Notes |
|---|---|---|
| `Series` | Enumeration | 60, 62, 63, 68, 69, MR (v0.1) |
| `Designation` | Enumeration | `Auto` + rows of the series; the list refreshes when `Series` changes |
| `Closure` | Enumeration | Open, Z, ZZ, RS, 2RS. A single closure sits on the top face (z = 0) |
| `Flanged` | Bool | Ignored with a warning if the row has no flange data |
| `DetailLevel` | Enumeration | **Envelope** (1 solid, fast), **Standard** (rings + balls + shields), **Detailed** (adds a cage) |
| `MatchTo` | Enumeration | Shaft (match bore) / Housing (match OD); used when `Designation = Auto` |
| `BaseObject` | LinkSub | Circular edge to attach to (optional) |
| `Invert`, `Offset` | Bool, Distance | Flip direction / shift along the axis |
| read-only | | `FullDesignation`, `BoreDiameter`, `OuterDiameter`, `Width`, `PitchDiameter`, `BallDiameter`, `BallCount` |

Local frame: the axis is +Z, the bearing occupies **z ∈ [−B, 0]**, and the flange sits at
z ∈ [−C1, 0]. With an attachment, z = 0 lands on the clicked edge's face and the bearing
extends *into* the material. That means into the hole for Housing, and onto the shaft for a
shaft-end edge (whose face normal points away from the shaft). The direction comes from the
planar face adjacent to the edge (`ancestorsOfType`), with a fallback to the circle axis.

Designation strings, using maker conventions: `608`, `608Z`, `608ZZ`, `608-RS`, `608-2RS`,
`F608ZZ`, `MF105ZZ`.

Face colors (steel rings and balls, brass cage, grey shields, black seals) are computed in
`execute` and applied by the view provider (`DiffuseColor`).

## 6. GUI

- One toolbar "Bearings" with one insert command per series, each with its own SVG icon.
- If circular edges are selected, insert one bearing per edge with `Designation = Auto`.
  Edges come from the shaft (bore match) or the hole (OD match), depending on whether the
  radius matches a bore or an OD better. Otherwise, insert at the origin with a
  maker-friendly default (608, 625, 6300, 688, 695, MR105).
- Everything else is edited in the property editor, as in Fasteners.
- Toolbar "Bearing tools": **Find bearing** (search panel) and **3D-printable bearing**
  (task panel). Both are task panels, so the 3D view stays usable.
- Printable bearings are edited later on their `BearingParameters` datum. The
  `PrintableBearing` object next to the bodies shows the catalog match and any error.

## 7. Testing

`tests/run_tests.py` runs with
`/Volumes/Silo/brew/FreeCAD.app/Contents/Resources/bin/freecadcmd tests/run_tests.py`:

1. Every row × {Open, ZZ, 2RS} × {flanged if available} × {Envelope, Standard, Detailed}:
   `isValid()`, bounding box ≈ (D or D1, B_eff), bore clear, expected solid count.
2. Balls don't overlap rings (`common` volume ≈ 0) for representative sizes.
3. Internals sanity: 608 → Z = 7, Dw ≈ 4; 6204 → Z = 8, Dw ≈ 8.
4. FeaturePython: the Auto match picks 608 for a Ø22 hole (Housing) and for a Ø8 shaft (Shaft).
   Placement puts z = 0 on the face and the body inside the hole or on the shaft.
5. Save, reopen and recompute (proxy serialization).

GUI checks (dev only, git-ignored in `tools/dev/`): `tools/dev/run_gui.sh
tools/dev/gui_smoke.py <log>` drives the panels in the real FreeCAD GUI. Scripts end with
`guikit.finish()`, which closes documents without saving and exits the process, so the
"save changes?" dialog can't block an unattended run. The runner also kills that FreeCAD
process if it outlives the script or a timeout. `guikit` also closes any dialog that
appears (message boxes, including macOS window-modal sheets that `activeModalWidget()`
doesn't report) and logs its text, so an unexpected warning can't hang a run.

Don't name test scripts `inspect.py`. It shadows the stdlib module and freecadcmd silently
prints nothing.

Notes from implementation:
- Cage = one pitch segment with one spherical pocket, patterned Z times (compound of
  segments). Cutting all pockets from a full ring took ~1 s per bearing; the segment
  approach takes ~0.13 s.
- `Shape.BoundBox` is loose for revolved arcs, so tests use `optimalBoundingBox(False, False)`.
- FeaturePython objects have no `isError()` in 1.1. Check `"Invalid" in obj.State`.
- Setting `obj.Shape` resets the placement, so `execute` restores it afterwards.

### v0.2: Maker essentials (in progress)

Decided 2026-10-09: the printable bearing is the author's **DeepGrooveBallBearing macro**
(`/Volumes/Silo/cad/deep-grove-ball-bearing/macro-git-repo`, MIT, printed and tested). It
is ported with its **PartDesign construction unchanged** (Races / Cage / Balls bodies, a
`BearingParameters` datum, sketches driven by expressions), not re-implemented as a
FeaturePython. **The workbench is now its home.** The macro repo stays as it is; point it
at the workbench once the workbench is published. This replaces the earlier
"print-in-place single solid" idea: the design is printed races + a printed snap-in cage +
bought balls.

- [x] **Printable bearing** (`PrintableBearing.py`, `PrintableBearingGui.py`,
  command `Bearings_PrintableBearing`):
  - Both macro modes: *Create races* (new App::Part "Bearing …") and *Groove selected body*
    (the selected PartDesign body becomes the races).
  - Task panel instead of a modal dialog. Same fields and tooltips as the macro.
  - **Catalog size** picker (filtered to the diameter the selected edge locks) and
    **ball presets** (3, 1/8", 4, 4.5 BB, 5, 6 airsoft = 5.95, 6, 1/4").
  - **Replace a standard bearing**: select a Bearing object, then run the command. Its
    size and placement are used, and it is hidden.
  - **Direction preset**: *Reverse direction* is pre-ticked so the races go into the hole
    or onto the shaft (the macro's default depended on the arbitrary sign of the circle
    axis).
  - **Live preview** in the 3D view while the panel is open (all modes, including groove):
    the ID and OD as labelled rings on both faces, drawn on top so they show through the
    part, and a see-through ghost of races (with the groove), balls and cage. It is built
    from plain Part profiles (`preview_shapes`, about 2 ms, no booleans) and placed by
    `preview_frame` exactly where the builders put the bearing. It is a scene-graph
    overlay only, never added to the document or undo history, and is removed however the
    panel closes. "Show preview" turns it off.
  - **`PrintableBearing` check object** in the Part: validates every later edit of
    `BearingParameters` (e.g. too many balls marks it invalid with the reason) and keeps
    the Part label in step with the size ("Bearing 608 (22x8x7)", "Bearing 22x8x8") until
    the user renames it. The geometry doesn't depend on it, so a document opened without
    the workbench still recomputes. It finds its Part through the tree; a link to the
    Part would form a dependency cycle.
  - **No automatic ball/cage sizing in the panel** (user decision, 2026-10-11): ball
    diameter, number of balls and the cage values start at the macro's defaults (4 mm,
    10 balls, cage 1.5 / 0.5 / 0.35 / 0.6). They change only when the user edits them,
    not on ID/OD/height edits, mode switches or catalog picks. The macro dialog adapted
    them and also clamped the cage thickness to half the ball, which confused users who
    don't know good sizes. Instead, a **status line** under the fields says what doesn't
    fit (e.g. "Number of balls must be between 1 and 9"), and OK refuses invalid values
    with a warning as before.
  - **Other diameter starts 15 mm from the selected edge** (user decision, 2026-10-11),
    in both modes: ID selected → OD = ID + 15; OD selected → ID = OD − 15, or OD / 2 when
    that leaves no bore (`other_diameter()`). Groove mode no longer measures the body's
    nearest outer cylinder for it (that gave e.g. OD 80 for a 30 mm bore in a large
    plate). The height is still the length of the selected bore or surface, and the
    status line flags it when the default 4 mm ball doesn't fit (e.g. a 2 mm plate).
  - **Default height 8 mm** for new races, with or without a selected edge (was
    0.4 × diameter). Groove mode keeps the selected bore's length; replacing a standard
    bearing keeps its width.
  - **Updates when a value is committed**, not per keystroke: number fields have keyboard
    tracking off, so status and preview refresh when the user leaves the field (click
    out / Tab) or clicks a spin arrow. Enter presses the panel's OK, as in every FreeCAD
    task panel.
  - `fit_values()` (the macro dialog's sizing logic as a plain function) remains only for
    scripting: `convert_bearing()` without explicit values. When 4 mm balls don't fit, its
    fallback snaps to the largest **standard (buyable) ball**.
  - The macro's `SendMsgToActiveView("ViewFit")` doesn't exist in FreeCAD 1.1 ("Unknown
    view command"). It is replaced by `ActiveView.fitAll()`. The macro itself has the same
    line.
- [x] **Find bearing** (`BearingSearchGui.py`, command `Bearings_Search`; logic in
  `BearingData.search()` / `parse_designation()`): search by **name, ID, OD or height**,
  in any combination, with a ± tolerance.
  - Names: prefix match (62 → all 62xx), flange/closure codes (`F688-2RS`, `MF105ZZ`,
    `6204-2RS1`), SKF miniature names (`618/8` → 688), size text (`8x22`, `8x22x7`).
  - Height also matches the shielded width (684ZZ = 4 mm).
  - Insert the hit as a standard bearing (with the parsed flange/closure, attached to the
    edges selected beforehand), or open the printable panel with that size.
- [x] **Fixes found while porting** (`BRselection.py`, shared by both bearing kinds):
  - Edges inside containers (App::Part / Body with their own placement) are resolved to
    global coordinates. Standard bearings attached to such edges were misplaced before.
  - Shaft vs hole is detected from the geometry (`cylinder_side`, from the macro), not by
    which diameter the size happens to match.
  - `BaseObject` is a `PropertyLinkSubGlobal` (no link-scope warnings when linking to a
    feature inside a Body).
  - Task panels return Qt button enums directly (PySide6 rejects `int()` on them).
- [ ] **Linear bearings** LMxxUU / LMxxLUU / LMxxUU-flanged (LM8UU first), with envelope and
  simplified detail.
- [ ] **Custom** designation (user d/D/B, internals still computed).
- [ ] "Explode" command: split a Standard/Detailed bearing into separate objects (inner ring,
  outer ring, balls) so the Assembly workbench can animate rotation.
- [ ] Inch R-series (R2…R12, R144…R188).
- [ ] **Export for printing**: one STL/3MF per printable body (Races, Cage).

### v0.3: Fit and seat tools
- **Seat cutter**: from a placed bearing, cut the pocket into the housing or turn the
  shaft seat. Choose a fit: press / slide / 3D-print press (housing bore + 0.1–0.2 mm,
  "crush ribs" option) or ISO fits (H7, J7 / k5, m6). Optional shoulder and DIN 471/472
  circlip groove.
  - Shoulder heights, fitted from SKF abutment data (146 bearings):
    shaft shoulder `da_min ≈ d + 0.168·(D − d)` (range 0.11–0.23) and housing shoulder
    `Da_max ≈ D − 0.170·(D − d)` (range 0.11–0.28). Fillet radius `ra_max = r` in 75 % of
    cases; use `ra = r`, but never more than r.
- Thrust ball bearings 511xx, small angular contact 7xx.
- BOM export (CSV of all bearings with designation and quantity).

### v0.4: Wider coverage
- Self-aligning 12/13/22/23, cylindrical NU/NJ, tapered 302/303/320 (ISO 355), needle
  NK/HK drawn cup, AXK thrust needle.

  estimate) + simple L10 life calculator.

### v0.5: Units and release
- Pillow blocks / flange units (UCP, UCF, UCFL, KP08/KFL08 for makers), rod ends,

## 9. Risks and notes

- **Accuracy of miniature data**: shielded widths and flange dims vary by vendor. Keep
  them in CSV so users can fix them easily, and flag them in the docs.
- **Performance**: Detailed mode on big assemblies. Keep the default at `Standard`, cache
  shapes by key, never fuse balls (compound only), and use one cage boolean.
- **Toponaming**: `BaseObject` references an edge by name (`Edge12`). It can break when
  the base changes, the same limitation as Fasteners. Revisit with FreeCAD 1.x's
  `App::PropertyLinkSub` + element maps later.
- **Assembly WB**: Standard/Detailed shapes are compounds. Joints attach to faces fine,
  but rotation needs the v0.2 "Explode".
